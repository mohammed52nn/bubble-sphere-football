# FOOTBALL BUBBLES — إكمال الواجهة

الطبقة الخلفية جاهزة (بحث AI، صور ويكيبيديا، أخبار حقيقية، تلخيص عربي، تخزين مؤقت) مع مكوّنات الفقاعة والخلفية والمُحمّل. المتبقي هو الواجهة الفعلية.

## ما سيُبنى

1. **مدير حقل الفقاعات** (`src/hooks/useBubbleField.ts`)
   - دورة حياة 35–50 ثانية: خروج فقاعة واحدة ودخول أخرى بدلًا من تحديث الشاشة كاملة.
   - توزيع مواضع بلا تعارض (شبكة مرنة + عمق) وأحجام متفاوتة حسب الشهرة.
   - تجميد الدورة عند فتح ملف لاعب أو الكتابة في البحث، واستئنافها بعد الإغلاق.
   - استبعاد اللاعبين الظاهرين حاليًا عند طلب مجموعة جديدة.

2. **`BubbleField`** — طبقة الفقاعات فوق خلفية الملعب، مع حالة تحميل (LoadingOrb) وحالة فراغ/فشل بلغة عربية هادئة.

3. **`ResearchBox`** — شريط بحث عربي (اسم لاعب، نادٍ، دوري، أو سؤال طبيعي) يعرض تفسير AI للاستعلام (`interpretation`)، زر إعادة الاكتشاف، وحالة الانتظار.

4. **`PlayerProfileOverlay`** — طبقة ملف اللاعب: صورة + بطاقة معلومات (النادي، المركز، الجنسية، العمر، القدم، الرقم، الطول، القيمة، التقييم)، السيرة، المسيرة، الإنجازات، الأرقام، ثم الأخبار بترتيب الأهمية مع المصدر والتاريخ ورابط خارجي، ومؤشر الثقة و«آخر تحديث» وزر تحديث. أي حقل غير مؤكد يظهر «غير متوفر من مصدر موثوق» بدل التخمين.

5. **الصفحة الرئيسية** (`src/routes/index.tsx`) — استبدال صفحة القالب: خلفية الملعب + ResearchBox + BubbleField + Overlay، وربطها بـ `discoverPlayers` / `getPlayerProfile` عبر TanStack Query.

6. **الجذر** (`src/routes/__root.tsx`) — `lang="ar"` و`dir="rtl"`، تحميل خطوط عربية عبر `<link>`، عناوين وميتا خاصة بالتطبيق بدل قيم القالب، و`<Toaster />` من sonner.

7. **جولة تلميع** — فحص فعلي في المتصفح على مقاس الهاتف: قراءة النصوص، تباعد، عمق الزجاج، سلاسة الحركة، أهداف اللمس، ثم إصلاح ما يظهر.

## ملاحظات تقنية

- كل نداءات AI/الأخبار تبقى داخل server functions الحالية؛ لا مفاتيح في المتصفح.
- التحميل الأولي من مكوّن العميل عبر `useQuery` (وليس loader) لتفادي بطء SSR وأخطاء التصيير المسبق.
- الحركة عبر CSS keyframes الموجودة في `styles.css` مع احترام `prefers-reduced-motion`.
- لا ألوان مكتوبة يدويًا في المكوّنات — فقط رموز التصميم الحالية.
